leetcode小抄：20. Valid Parentheses

Given a string s containing just the characters '(', ')', '{', '}', '[' and ']', determine if the input string is valid.

An input string is valid if:

  1. Open brackets must be closed by the same type of brackets.
  2. Open brackets must be closed in the correct order.
  3. Every close bracket has a corresponding open bracket of the same type.

Example 1:

Input: s = "()" Output: true

Example 2:

Input: s = "()[]{}" Output: true

Example 3:

Input: s = "(]" Output: false

Constraints: $ 1 <= s.length <= 10^{4} $ s consists of parentheses only '()[]{}'

solution 1 聪明方法

不能直接切片排序会影响原本的字符串，失去顺序信息，简单统计个数也没有意义。

实现步骤

利用栈来实时检查括号的匹配情况，具体步骤如下：

  1. 初始化一个空栈。
  2. 遍历字符串s中的每个字符。
  3. 如果遇到一个开括号(、{或[，将其压入栈中。
  4. 如果遇到一个闭括号)、}或]，则检查栈顶的元素是否是与之匹配的开括号：
    • 如果是，弹出栈顶元素，表示成功匹配了一对括号；
    • 如果不是，或者栈为空（没有可匹配的开括号），则说明字符串无效。
  5. 遍历结束后，如果栈为空，说明所有括号都成功匹配，返回True；否则，返回False。

关键数据结构：字典

这里的映射关系是：

  • 右圆括号 ) 映射到左圆括号 (
  • 右大括号 } 映射到左大括号 {
  • 右方括号 ] 映射到左方括号 [

  1. 简化匹配检查：在遍历输入字符串 s 的过程中，每遇到一个闭合括号，我们就可以直接通过 mapping 查找它所对应的开括号。这种方式相较于直接在代码中写多条件判断（如 if char == ')' and top_of_stack == '('）更为简洁和易于理解。

  2. 提高代码可维护性：如果未来括号的种类需要扩展，只需在 mapping 中添加相应的键值对即可，无需改动匹配逻辑的主体代码，增强了代码的扩展性和可维护性。

  3. 优化匹配逻辑：在实际的匹配过程中，通过从栈顶弹出的元素与 mapping 中当前闭合括号对应的开括号进行比较，可以快速判断括号是否匹配。

关键数据结构：字典 用法说明

字典是一种可变容器模型，且可存储任意类型对象。字典的每个键值对用冒号 : 分割，每对之间用逗号 , 分隔，整个字典包括在花括号 {} 中。

例子：创建一个简单的字典，用于存储学生分数，并查询特定学生的分数。

关键数据结构：栈

  1. 实时匹配检查

  • 存储未匹配的开括号：遍历输入字符串时，每当遇到一个开括号（(、{、[），就将其压入栈中。这样，栈中始终保存着所有尚未找到匹配闭括号的开括号。

  • 即时验证闭括号：遇到闭括号（)、}、]）时，从栈顶取出一个开括号，检查它是否与当前闭括号匹配。如果匹配，说明这对括号是有效的，继续处理下一个字符；如果不匹配或栈为空（意味着没有匹配的开括号），则输入字符串无效。

  1. 维护顺序：

由于栈遵循LIFO原则，它自然地保持了开括号的逆序，这恰好与闭括号出现的顺序相匹配。这样，不需要额外的逻辑来跟踪括号的顺序，栈本身就维护了正确的匹配顺序。

  1. 空间效率：

栈只需要存储未匹配的开括号，空间需求与输入字符串中最大未匹配开括号序列长度成正比，对于大多数情况而言，这是一个相对较小的数量，保证了算法的空间效率。

  1. 时间效率：

每个字符至多被访问两次（一次压入，一次匹配或弹出），因此整个算法的时间复杂度为O(n)，其中n是输入字符串的长度。这是处理此类问题的最优复杂度，因为至少需要遍历一次字符串来检查所有括号。

关键数据结构：栈 用法说明

虽然Python标准库没有直接提供栈的类，但你可以使用列表（List）来模拟栈的行为，因为列表支持两端操作，特别是使用append()方法在列表末尾添加元素（模拟压栈）和pop()方法移除末尾元素（模拟弹栈）。

核心思路

使用栈来解决括号匹配问题的思考方向基于以下几个核心逻辑和认识：

  1. 即时匹配需求：括号的有效性需要即时验证，即每遇到一个闭合括号，必须立即确定是否有与之匹配的开括号。栈作为一种后进先出（LIFO, Last In First Out）的数据结构，非常适合用来存储这些待匹配的开括号。

  2. 顺序依赖性：括号的顺序对于有效性至关重要。例如，在看到一个右括号之前，理论上应当有一个对应的左括号出现过，且这个左括号应当比右括号更早出现。栈可以帮助我们记住这些顺序信息。

  3. 平衡问题转换：括号匹配问题可以转换为检查序列是否平衡的问题。栈可以很好地帮助我们维护这种平衡状态，每当遇到开括号就入栈，遇到闭括号就尝试与栈顶的开括号匹配并出栈。如果序列结束时栈为空，说明所有的开括号都有相应的闭括号与之匹配，即序列是平衡的。

  4. 动态性：在处理输入字符串时，我们不知道也不需要提前知道确切的括号对数量或位置，栈能够适应这种动态性，根据读取的字符实时调整。

因此，面对括号匹配这类需要检查元素间依赖关系且具有即时验证需求的问题时，自然而然会想到使用栈。这种方法直观、高效，能够以线性时间复杂度O(n)完成任务，其中n是输入字符串的长度。
