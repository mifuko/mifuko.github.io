leetcode小抄：13. Roman to Integer

Roman numerals are represented by seven different symbols: I, V, X, L, C, D and M.

Symbol Value I 1 V 5 X 10 L 50 C 100 D 500 M 1000

For example, 2 is written as II in Roman numeral, just two ones added together. 12 is written as XII, which is simply X + II. The number 27 is written as XXVII, which is XX + V + II.

Roman numerals are usually written largest to smallest from left to right. However, the numeral for four is not IIII. Instead, the number four is written as IV. Because the one is before the five we subtract it making four. The same principle applies to the number nine, which is written as IX. There are six instances where subtraction is used:

  • I can be placed before V (5) and X (10) to make 4 and 9.
  • X can be placed before L (50) and C (100) to make 40 and 90.
  • C can be placed before D (500) and M (1000) to make 400 and 900.

Given a roman numeral, convert it to an integer.

Example 1:

Input: s = "III" Output: 3 Explanation: III = 3.

Example 2:

Input: s = "LVIII" Output: 58 Explanation: L = 50, V= 5, III = 3.

Example 3:

Input: s = "MCMXCIV" Output: 1994 Explanation: M = 1000, CM = 900, XC = 90 and IV = 4.

Constraints:

  • 1 <= s.length <= 15
  • s contains only the characters ('I', 'V', 'X', 'L', 'C', 'D', 'M').
  • It is guaranteed that s is a valid roman numeral in the range [1, 3999].

solution 1 笨蛋方法

定义了一个映射表roman_to_int_map，用于快速查找每个罗马数字字符对应的整数值。然后，通过遍历输入的罗马数字字符串，逐个字符进行处理。

对于每一个字符，先获取其对应的整数值，如果这个值大于前一个字符的值（表明可能涉及到减法规则），则从总结果中减去两倍的前一个值再加当前值（这样做是为了抵消之前加上去的前一个值，并加上当前值）。否则，直接加上当前值。

在每次迭代后，更新 prev_value 为当前值，以便于下一次迭代时进行比较。最后返回累加的结果 result 即可。

solution 3 聪明方法

通过一次遍历来完成转换，从右向左遍历字符串，这样可以避免显式地检查特殊减法规则组合，而是通过比较当前字符代表的值和前一个字符的值来自动处理加法和减法。

核心思路

1. 逆序遍历（从右到左）

  • 原因：罗马数字的减法规则（如 IV 表示 4，CM 表示 900）要求我们理解每个字符在序列中的相对位置。从右到左遍历，我们可以自然地应用这些规则，无需特别检查每个可能的减法规则组合。每个字符仅需与前一个字符的关系来决定其对总和的贡献。

2. 累积求和与减法规则的隐式应用

  • 累积求和：遍历过程中，我们对每个字符对应的数值进行累加。但是，如果遇到一个比前一个字符数值小的情况（例如，从左向右看是“大数在前，小数在后”的情况，逆序遍历时则是相反），我们知道这是一个减法规则的应用，需要从前一个累计值中减去这个较小数值的两倍（实际上就是抵消前一数值的贡献，加上当前的实际贡献）。

  • 例子：考虑 "CM"（900），逆序遍历时我们先遇到"M"（1000），然后是"C"（100）。正常情况下，我们应该加上"C"的值，但由于"C"在"M"之前且值小，实际上我们应当理解为"C"是从"M"中减去的，即减去1000再加回100，等同于加上-100（即减去100）。

3. 代码中的实现

  • 初始化：设置 total = 0 作为累计总和的起始值，prev_value = 0 作为前一个字符值的初始值，用于比较。

  • 遍历与计算：对字符串 s 进行逆序遍历，对于每个字符 char：

    • 查找其对应的数值 curr_value。
    • 比较 curr_value 和 prev_value：
      • 如果 curr_value >= prev_value，说明是正常累加，total += curr_value。
      • 如果 curr_value < prev_value，说明遇到了减法规则，实际上我们已经通过逆序遍历和直接减法处理了这种情况，直接累加即可。
    • 更新 prev_value = curr_value 以供下一次迭代使用。

  • 返回结果：遍历完成后，total 就是罗马数字字符串转换成的整数值。

特例处理也通过：49 = "XLIX"

"XL" 表示 40（即 50 - 10，但作为一个整体它有特定值40） "IX" 表示 9（即 10 - 1，同理作为一个整体代表9）

  1. 初始化: 首先，定义了一个罗马数字到整数的映射 roman_map，并初始化了总和 total 为 0，以及前一个字符的索引 prev_index 为 0。

  2. 遍历字符串: 使用 enumerate 函数遍历字符串 s，这样可以在每个循环中同时获得当前字符 char 和它的索引 i。

  3. 计算当前值: 对于每个字符，通过 roman_map[char] 获取其对应的整数值 curr_value。

  4. 减法规则处理:

    • 通过条件 if i > 0 and curr_value > roman_map[s[prev_index]] 检查当前字符是否比前一个字符代表的数值大，这暗示着可能遇到了减法规则。例如，在 "XLIX" 中，当遍历到 "L" 时，它比前一个字符 "X" 大，符合减法规则。
    • 如果满足条件，说明当前字符和前一个字符构成减法规则组合，如 "XL" 或 "IX"。这时，不是简单相加，而是要从当前值 curr_value 中减去两倍的前一个值，再加上当前值（实际上这里表述稍有误导，正确理解应该是直接计算减法规则的值，例如 "XL" 直接理解为 40，而不是 50 - 2*10），但核心思想是识别并应用减法规则。
    • 如果不满足条件，即当前字符不比前一个字符大，就直接将当前值累加到总和 total 中。

  5. 更新前一索引: 在每次循环结束时，更新 prev_index = i，以便在下一次迭代时可以正确地与当前字符进行比较。

  6. 返回结果: 遍历完成后，返回累计的总和 total，即罗马数字字符串转换后的整数值。

针对 "XLIX" 的具体处理流程：

  • 遇到 "X"，加 10；
  • 遇到 "L"，发现它比前一个字符 "X" 大，这是 "XL" 的减法规则，直接理解为加 40（而不是50-10的过程）；
  • 遇到 "I"，加 1；
  • 遇到 "X" 后的 "IX"，发现 "I" 比 "X" 小，这是 "IX" 的减法规则，直接理解为加 9（而不是10-1的过程）。

最终，累加得到 10 + 40 + 1 + 9 = 49，正确转换了 "XLIX" 到整数 49。

时空复杂度

时间复杂度 (Time Complexity)

代码的核心是一个遍历罗马数字字符串s的循环，使用for char in reversed(s):。这意味着循环会遍历字符串s中的每一个字符一次。因为循环是基于字符串的长度进行的，所以循环的次数与字符串s的长度成正比。

  • 循环内操作：循环内的操作主要是查找字符对应的整数值、比较当前值与前一个值、以及进行加法或减法运算，这些操作的时间复杂度都是常数时间O(1)。

综上所述，整体的时间复杂度由循环决定，即O(n)，其中n为字符串s的长度。这是因为我们必须至少查看字符串中的每个字符一次来确定其对应的数值并累计结果。

空间复杂度 (Space Complexity)

  • 局部变量：代码中定义了几个局部变量，包括roman_map（一个固定大小的字典）、total、prev_value和char。roman_map的大小是固定的，不依赖于输入字符串的长度，因此占用的空间是常量级别的。total、prev_value和char也都是存储单个值的变量，因此它们的空间复杂度也是O(1)。

  • 输入字符串：虽然输入字符串s是函数的参数，但在分析空间复杂度时通常不考虑输入数据所占用的空间，除非对其进行复制或修改导致额外的空间消耗。这里没有对s进行复制，只是原地遍历。
