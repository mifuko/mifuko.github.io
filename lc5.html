leetcode小抄：15. 3Sum

发表于2024-05-21|更新于2024-05-21|leetcode
|字数总计:1.8k|阅读时长:7分钟|阅读量:

Given an integer array nums, return all the triplets [nums[i], nums[j], nums[k]] such that i != j, i != k, and j != k, and nums[i] + nums[j] + nums[k] == 0.

Notice that the solution set must not contain duplicate triplets.

Example 1:

Input: nums = [-1,0,1,2,-1,-4] Output: [[-1,-1,2],[-1,0,1]] Explanation: nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0. nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0. nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0. The distinct triplets are [-1,0,1] and [-1,-1,2]. Notice that the order of the output and the order of the triplets does not matter.

Example 2:

Input: nums = [0,1,1] Output: [] Explanation: The only possible triplet does not sum up to 0.

Example 3:

Input: nums = [0,0,0] Output: [[0,0,0]] Explanation: The only possible triplet sums up to 0.

Constraints:

3<=nums.length<=3000 3 <= nums.length <= 3000 3<=nums.length<=3000 −105<=nums[i]<=105 -10^{5} <= nums[i] <= 10^{5} −105<=nums[i]<=105

solution 1 笨蛋方法

确保能够正确处理包含多个0的情况以及能够找到所有可能的三元组组合，而不仅仅是和为0的直接相反数情况。关键在于全面地遍历并利用哈希表来记录和检查元素，同时处理特殊情况。

复杂度

  • 时间复杂度：

此实现中，首先进行了排序，排序的时间复杂度是O(n log n)。之后是两层循环，外层循环是n次，内层循环在最坏情况下也是n次，但因为有跳过重复元素的逻辑，实际次数会少一些。然而，最内层还涉及了查找target - nums[j]是否在剩余数组中的操作，这在最坏情况下也是O(n)。因此，总体时间复杂度接近但略高于O(n^2)。准确地说，由于排序的存在，最终的时间复杂度应考虑为O(n log n + n2)，但通常排序的代价在大n下占主导，所以可以粗略估计为O(n2)。

  • 空间复杂度：

此实现中，除了输入数组外，主要额外空间消耗来自于结果列表res，其最坏情况下可能存储n/3个三元组（如果数组中所有元素满足条件的话），因此空间复杂度为O(n)。

solution 2 聪明方法

双指针法（Two Pointer Technique）是一种在数组或列表中寻找满足特定条件的元素对（或元素组合）的高效算法思想，还适用于许多其他数组处理问题，如“容器盛水”、“寻找目标区间”等。

核心思路

  1. 排序：首先对给定数组进行排序。排序是双指针法的基础，它允许我们在不重复检查元素的情况下有效地寻找目标组合。

  2. 固定一个元素：遍历排序后的数组，选定一个元素（设为 nums[i]），将它作为三元组的第一个数。因为我们不希望重复使用相同的元素，所以在遍历过程中，如果当前元素与前一个元素相同，则跳过，避免产生重复解。

  3. 设置两个指针：在当前元素之后，设置两个指针 left 和 right，初始时分别指向 i+1 和数组的最后一个元素。left 指向的元素和 right 指向的元素将与 nums[i] 组成可能的三元组。

  4. 移动指针：

    • 如果 nums[i] + nums[left] + nums[right] < 0，说明三数之和太小，为了增大和，需要将左侧指针 left 向右移动一位（即增大左侧元素的值）。
    • 如果 nums[i] + nums[left] + nums[right] > 0，说明三数之和太大，为了减小和，需要将右侧指针 right 向左移动一位（即减小右侧元素的值）。
    • 如果 nums[i] + nums[left] + nums[right] == 0，找到了一个符合条件的三元组，将其添加到结果集中。为了避免重复，找到一个解后，需要移动指针继续寻找下一个可能的解，这里同样需要跳过重复元素。

  5. 重复步骤：重复步骤3和4，直到遍历完所有可能的中间元素 nums[i]。

复杂度

  • 时间复杂度：

此实现中，首先进行了一次排序，时间复杂度为O(n log n)。然后是一层循环遍历数组（n次），内部使用双指针进行线性扫描，每次移动一个指针，直到两个指针相遇，这在最坏情况下也是O(n)。因此，整体时间复杂度为排序的O(n log n)加上O(n)的双指针扫描，最终为O(n log n)。这是因为在大n情况下，排序操作的时间成本占主导地位。

  • 空间复杂度：

与之前的实现相似，优化后的版本主要额外空间消耗仍然是用于存储结果的列表res，空间复杂度为O(n)。
